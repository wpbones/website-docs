# Boilerplates

WP Bones has 14 boilerplates on GitHub, all built on the same v2 infrastructure (webpack + yarn +
TypeScript + Jest + Prettier). Four of them are starting points for a front-end stack and have a
page of their own here; the other ten each demonstrate one part of the framework. Start from the
stack you want, or open the demo of the feature you are learning.

- **Base** — the minimum starter: JS/TS, SCSS/LESS/CSS, a small React sample, a Jest test. Use
  this if you want the leanest possible scaffold.
- **TypeScript** — a focused TypeScript showcase: interfaces, generics, discriminated unions, type
  guards, utility types. Great to learn idiomatic TS in a WordPress plugin.
- **ReactJS (WP libraries)** — React using only WordPress runtime libraries:
  `@wordpress/components`, `@wordpress/data`, `@wordpress/hooks`, `@wordpress/i18n`. Native
  wp-admin look, no third-party UI kit.
- **Mantine UI** — a full admin app built on Mantine: theme customization, dark mode toggle, tabs,
  form validation, modals, notifications, and a DataTable fed by WordPress AJAX.

## Try them in the browser

Every boilerplate has a [WordPress Playground](https://wordpress.org/playground/) blueprint. The
**Playground** link, in the table above or on each starting point's page, spins up a throwaway
WordPress install with the plugin pre-activated.

## How to start from one

Each boilerplate is a GitHub **template repository**. You have three options:

1. **Use as a template** — click "Use this template" on GitHub and clone your new repo.
2. **Clone + rename** — clone the repo locally and run `php bones rename "My Plugin Name"` to
   reset the namespace.
3. **Playground first** — test-drive in Playground, then grab the `.zip` from
   [wpbones.com](https://wpbones.com).

<Callout type="info">
All 14 boilerplates share the same bones CLI, the same yarn scripts
(`dev`/`build`/`test`/`format`/`lint`), and the same webpack auto-discovery rules. Moving from one
starting point to another is mostly a matter of swapping `dependencies` in `package.json`.
</Callout>

## What stays the same across all of them

- [`webpack.config.js`](/docs/core-plugin-files/webpack-config) with auto-discovery of entries
- [`package.json`](/docs/core-plugin-files/package-json) scripts: `dev`, `build`, `test`, `format`,
  `lint`
- `tsconfig.json`, `.prettierrc`, `jest.config.js`
- The bones CLI (`php bones --help`) with `make:*` and `migrate:to-v2`
- `plugin/` folder (PSR-4 namespace root), `config/`, `bootstrap/`, `resources/views/`

## What differs

- **`dependencies`** in `package.json` — only the UI kit / libraries the boilerplate demoes.
- **`resources/assets/apps/`** — the demo app(s) specific to each boilerplate.
- **The PHP side, in the feature demos** — the part of the framework each one shows: `api/`,
  `database/`, `plugin/CustomPostTypes/`, `plugin/Providers/`, `config/options.php` and so on.
- **The admin pages** — each boilerplate's pages show their own sources inline, so learners can
  read them (plain PHP views, and Blade in the Blade boilerplate).
