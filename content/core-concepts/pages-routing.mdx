# Pages Routing

This document explains how to add page routing in WP Bones without creating a menu. It describes how to define page routes in the `config/routes.php` file, similar to menu routing. You can get the URL of a page using the `$plugin->getPageUrl` method. Additionally, it explains how to create custom admin pages by adding PHP files to the `pages` folder.

## Overview

In addition to [Menus Routing](menus-routing), you may add a page routing without creating a menu. 

In the `config/routes.php` you'll find an array with the page routing settings:

```php copy filename="config/routes.php"
<?php
if (!defined('ABSPATH')) {
    exit();
}

/*
|--------------------------------------------------------------------------
| Custom page routes
|--------------------------------------------------------------------------
|
| Here is where you can register all page routes for your custom view.
| Then you will use $plugin->getPageUrl( 'custom_page' ) to get the URL.
|
*/

return [

  'custom_page' => [
    'title'      => 'Title of page',
    'capability' => 'manage_options',
    'route'      => [
      'get' => 'Dashboard\DashboardController@customPage'
    ]
  ]

];
```

As you can see, a page route is very similar to a menu. Also, the `route` key works like the `route` menu. You can get the URL of a page by using `$plugin->getPageUrl` method. For example, to get the URL of the above custom page, please use:

```php copy
$url = $plugin->getPageUrl( 'custom_page');
// you'll get something like
// http://domain.com/wp-admin/admin.php?page=custom_page
```

### Who can open the page

A page route has no menu entry, and WordPress lets any logged-in user open a page like that, subscribers included. WP Bones checks the `capability` key for it: a user without that capability gets WordPress's own *"Sorry, you are not allowed to access this page."*, with a 403 status, before any `load` callback or controller method runs, whatever the HTTP verb.

Without the key, the page asks for `manage_options`: only administrators can open it. Give it the capability that fits the task, or `read` to open it to every user with a role on the site:

```php copy filename="config/routes.php" {4}
return [
  'custom_page' => [
    'title'      => 'Title of page',
    'capability' => 'read',
    'route'      => [
      'get' => 'Dashboard\DashboardController@customPage'
    ]
  ]
];
```

The key takes a string: anything else raises a notice, and the page asks for `manage_options`.

<Callout type="warning">
Since `v3.0.0` a page route without a `capability` asks for `manage_options`. From `v2.1.2` to 2.x it asked for `read`, any logged-in user; before `v2.1.2` the key was not read at all. `php bones migrate:to-v3` lists the page routes that declare no capability: add `'capability' => 'read'` to the ones that must stay open to every logged-in user. See [Migrating to v3](/docs/migrating-to-v3).
</Callout>

## Custom Admin Pages folder

You may also create a custom page by creating a file in the folder `pages`.
Let's say you want to create a custom page called `custom_page`. You have to create a file called `custom_page.php` in the `pages` folder.

```php copy
<?php

use WPKirk\WPBones\Routing\Pages\Support\Page;

class CustomPage extends Page
{
    public function title()
    {
        return "Hello, Custom Page!";
    }

    // Who can open the page. Leave it out and the page asks for `manage_options`.
    public function capability(): string
    {
        return 'manage_options';
    }

    public function render()
    {
        return $this->plugin->view('dashboard.custom_page');
    }
}
```

<Callout >
The class name is not important. You can use any name you want. The most important thing is the name of the file. In this case, the file name is `custom_page.php`. This means that the slug of the page will be `custom_page`.
</Callout>

A page in the `pages` folder has no menu entry either, so it gets the same check as a page route: a public `capability()` method, without required arguments, says which capability opens it (since `v2.1.2`). Without the method, the page asks for `manage_options` since `v3.0.0` (`read` up to 2.x): return `'read'` from `capability()` to open it to every logged-in user.

You will be able to get the URL of the custom page by using `$plugin->getPageUrl` method. For example, to get the URL of the above custom page, please use:

```php copy
<?php $plugin->getPageUrl('custom_page'); ?>
```

## Forms

Since `v3.0.0` a request to a page route, or to a page in the `pages` folder, that is not a `GET` or a `HEAD` must carry the plugin's nonce, as for a menu item: print `$plugin->csrfField()` in the form. See [Forms and the nonce](menus-routing#forms-and-the-nonce).

A page that receives a form posted from another site through the user's browser, a payment or sign-in provider returning to it for instance, turns the check off and checks the request itself. A page route does it with `'csrf' => false` in its `route`:

```php copy filename="config/routes.php" {8}
return [
  'connect_return' => [
    'title'      => 'Connect your account',
    'capability' => 'manage_options',
    'route'      => [
      'get'  => 'Dashboard\ConnectController@index',
      'post' => 'Dashboard\ConnectController@store',
      'csrf' => false,
    ]
  ]
];
```

A page in the `pages` folder does it with a public `csrf()` method, without required arguments, that returns `false`:

```php copy filename="pages/connect_return.php" {12-15}
<?php

use WPKirk\WPBones\Routing\Pages\Support\Page;

class ConnectReturnPage extends Page
{
    public function capability(): string
    {
        return 'manage_options';
    }

    public function csrf(): bool
    {
        return false;
    }

    public function render()
    {
        return $this->plugin->view('dashboard.connect_return');
    }
}
```

Without the nonce, the page has to check the request itself, a signature or a secret for instance.
