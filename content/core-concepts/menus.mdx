# Menus

This document explains how to set custom menus in WP Bones using the `config/menus.php` file. The file returns an array representing the menu structure, which can be left empty if no menu is needed. It provides an example of a typical menu structure and explains how menu slugs are generated. The menu page slug for the first item will be `wp_kirk_slug_menu`, and subsequent items will have slugs like `wp_kirk_1`, `wp_kirk_2`, etc.

## Overview

You can set your custom menu in `config/menus.php` file. This file returns an array representing the menu structure. You can leave this array empty if you don't need a menu. Let me show you a typical menu structure.


```php filename="config/menus.php" copy
if (!defined('ABSPATH')) {
    exit();
}

/*
|--------------------------------------------------------------------------
| Plugin Menus routes
|--------------------------------------------------------------------------
|
| Here is where you can register all of the menu routes for a plugin.
| In this context, the route is the menu link.
|
*/

return [
  'wp_kirk_slug_menu' => [
    "page_title" => "WP Kirk Page title",
    "menu_title" => "WP Kirk Menu title",
    'capability' => 'read',
    'position'   => null,
    'icon'       => 'dashicons-admin-plugins',
    'items'      => [
      [
        "page_title" => "Main View",
        "menu_title" => "Main View",
        'capability' => 'read',
        'route'      => [ 'get' => 'Dashboard\DashboardController@firstMenu' ],
      ],
      [
        "page_title" => "Ajax Example",
        "menu_title" => "Ajax Example",
        'capability' => 'read',
        'route'      => [ 'get' => 'Dashboard\DashboardController@secondMenu' ],
      ]
    ]
  ]
];
```

<Callout type="info">
**Under the hood**<br/>
The menu page slug for the first item will be `wp_kirk_slug_menu`. For the second item, it will be `wp_kirk_1`. For the third item, it will be `wp_kirk_2`.
In other words, the menu slug is `{namespace}_{index_sub_menu}`.
</Callout>

Of course, you can replace the submenu index with your own array key:

```php filename="config/menus.php" copy
return [
  'wp_kirk_slug_menu' => [
    "page_title" => "WP Kirk Page title",
    "menu_title" => "WP Kirk Menu title",
    'capability' => 'read',
    'position'   => null,
    'icon'       => 'dashicons-admin-plugins',
    'items'      => [
      'my-main-view' => [
        "page_title" => "Main View",
        "menu_title" => "Main View",
        'capability' => 'read',
        'route'      => [ 'get' => 'Dashboard\DashboardController@firstMenu' ],
      ],
      'example' => [
        "page_title" => "Ajax Example",
        "menu_title" => "Ajax Example",
        'capability' => 'read',
        'route'      => [ 'get' => 'Dashboard\DashboardController@secondMenu' ],
      ]
    ]
  ]
];
```

In this case, you'll get the first item:

```
/wp-admin/admin.php?page=wp_kirk_my_main_view
```

and

```
/wp-admin/admin.php?page=wp_kirk_example
```

<Callout type="info">
**Under the hood**<br/>
The array key will be sanitized in lowercase, and any of the character `-` will be replaced by `_`.
</Callout>

## Get a menu item URL

You can get a menu item URL by using the `getMenuUrl()` method from your plugin instance. This method accepts the menu slug or the menu index. For example:

```php copy
$plugin->getMenuUrl('example'); // will return /wp-admin/admin.php?page=wp_kirk_example
```

or

```php copy
$plugin->getMenuUrl(1); // will return /wp-admin/admin.php?page=wp_kirk_1
```

## Default values

You may avoid inserting the following array items:

```
icon         : blank
page_title   : menu_title
capability   : manage_options
position     : null
```    

The `capability` key is optional for both menu and submenu items. The default value of the key `capability` in the root menu is `manage_options` when it is not set: only administrators see the menu. The default value of the key `capability` in the submenu remains the same as the root menu when it is not set. For example:

```php filename="config/menus.php" copy
if (!defined('ABSPATH')) {
    exit();
}

/*
|--------------------------------------------------------------------------
| Plugin Menus routes
|--------------------------------------------------------------------------
|
| Here is where you can register all of the menu routes for a plugin.
| In this context, the route is the menu link.
|
*/

return [
  'wp_kirk_slug_menu' => [
    "page_title" => "WP Kirk Page title",
    "menu_title" => "WP Kirk Menu title",
    'capability' => 'manage_options',
    'position'   => null,
    'icon'       => 'dashicons-admin-plugins',
    'items'      => [
      [
        "page_title" => "Main View",
        "menu_title" => "Main View",
        'route'      => [ 'get' => 'Dashboard\DashboardController@firstMenu' ],
      ]
    ]
  ]
];
```

The submenu "Main View" capability will be set to `manage_options`.

To open a menu to every logged-in user, set `'capability' => 'read'` on the menu itself, as in the first example on this page. With `read` on an item only, under a menu that asks for `manage_options`, a subscriber sees the menu but cannot open its first page.

<Callout type="warning">
Since `v3.0.0` a menu without a `capability` asks for `manage_options`. Up to 2.x it asked for `read`: every logged-in user, subscribers included, saw it and could open its pages. `php bones migrate:to-v3` lists the menus that declare no capability. See [Migrating to v3](/docs/migrating-to-v3).
</Callout>

## Icon

The `icon` key takes what `add_menu_page()` takes, plus the images of your plugin:

| Value | Example | What WordPress draws |
| --- | --- | --- |
| A Dashicons class | `dashicons-admin-plugins` | the Dashicons glyph (on WordPress 7.2, its SVG counterpart when there is one) |
| An icon name, WordPress 7.2+ | `core-admin/pin` | the registered SVG icon |
| A `data:` URI | `data:image/svg+xml;base64,…` | your SVG, colored by the admin scheme |
| An absolute URL | `https://cdn.example.com/menu.png` | that image |
| `none` | `none` | nothing: you add the icon with CSS on `div.wp-menu-image` |
| Anything else | `wpbones-logo-menu.png` | an image of your plugin's `public/images/` folder |

```php filename="config/menus.php" copy
'icon' => 'wpbones-logo-menu.png', // /public/images/wpbones-logo-menu.png
```

### SVG icons on WordPress 7.2

WordPress 7.2 draws the admin menu with inline SVG icons, and a menu can name a registered icon: one of core's `core-admin` collection, or one you register with `wp_register_icon()`. Before 7.2 an icon name means nothing to WordPress, and WP Bones reads it as a file name, so gate it to keep a Dashicon on earlier versions:

```php filename="config/menus.php" copy
'icon' => function_exists('wp_is_valid_icon_name') ? 'core-admin/pin' : 'dashicons-admin-post',
```

On 7.2 a lowercase `folder/name` with no extension is read as an icon name, so keep an extension on the image files you put in subfolders of `public/images/`.

<Callout type="info">
Since `v3.4.0`. Up to v3.3.1 an icon name, `none` and an absolute URL were all read as file names of `public/images/`, and drew a broken image.
</Callout>

## Custom Post Type attachment

You could have your own Custom Post Type as a standard WordPress menu. To attach your custom menu below the Custom Post item menu, just replace the first menu key with something like the following one:

```php copy
return [
  'edit.php?post_type=your_cpt_id',
...
```

Where `your_cpt_id`, enter the Custom Post Type ID. So, your menu will be attached under the Custom Post Type submenu items.

## Menu View Controller

As you can see from the code above, the view is handled by a **Laravel**-style syntax. In other words, the `view` key is bound to a View Controller's methods. The syntax is very easy: `ViewController@method`.

Of course, you will add the namespace as necessary.
