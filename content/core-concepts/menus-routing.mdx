# Menus Routing

This document explains menu routing in WP Bones, which differs from Laravel's routing system. It supports basic HTTP verbs like GET, POST, PUT, PATCH, and DELETE. Examples show how to define routes for different HTTP methods and handle form method spoofing for unsupported actions. Additionally, it introduces the `resource` key for calling default methods in view controllers, simplifying route definitions by using standard methods like `index` and `store`.

## Overview

In WordPress as well as WP Bones architecture, the routing is quite different from Laravel. Instead of a true routing system, there is menu routing. However, you can still handle basic HTTP verbs such as GET, POST, PUT, PATCH, and DELETE. In the example above, we used the `get` verb in the `route` key. If your view contains a form with a POST method, you can use:

```php copy
...
  'route' => [
    'get'  => 'Dashboard\DashboardController@secondMenu',
    'post' => 'Dashboard\DashboardController@updateValues'
  ]
...  
```

In this case, when an HTTP POST request is made, the method `updateValues` in `Dashboard\DashboardController` will be called.

## Forms and the nonce

Since `v3.0.0` every request to a WP Bones admin page that is not a `GET` or a `HEAD` must carry the plugin's nonce. That covers the menu items, the [page routes](pages-routing) and the pages in the `pages` folder. Print it inside every form that posts to one of them with `$plugin->csrfField()`:

```php filename="resources/views/dashboard/second-menu.php" copy {2}
<form action="" method="post">
  <?php echo $plugin->csrfField(); ?>

  <input type="text" name="title" value="" />

  <button class="button">Save</button>
</form>
```

In a Blade view, print it unescaped:

```php filename="resources/views/dashboard/second-menu.blade.php" copy {2}
<form action="" method="post">
  {!! $plugin->csrfField() !!}

  <input type="text" name="title" value="" />

  <button class="button">Save</button>
</form>
```

`csrfField()` returns the hidden fields of [`wp_nonce_field()`](https://developer.wordpress.org/reference/functions/wp_nonce_field/): the nonce, in a field named `_wpbones_nonce`, and the referer. The name is not `_wpnonce`, so a form can keep a `wp_nonce_field()` of its own beside it. The nonce action is `$plugin->csrfAction()`, the plugin's slug followed by `_csrf`. A script that posts to the page itself sends `wp_create_nonce($plugin->csrfAction())` in a `_wpbones_nonce` field, in the query string, or, for a `fetch()` with a JSON body, in an `X-WPBones-Nonce` header.

WP Bones checks the nonce on the page's `load-{hook}` action, before any `load` callback, and again before the page renders. A request without it, or with a wrong or expired one, gets WordPress's own *"The link you followed has expired."* page, with a 403 status: neither the `load` callbacks nor the controller method run. WordPress's own forms that post to the page they are on carry a nonce of their own and go through: Screen Options and the filesystem credentials form.

<Callout type="warning">
Up to 2.x a WP Bones admin page called `store()`, `update()` or `destroy()`, and ran its `load` callbacks, for any request: a form on another site could post to it with the cookies of a logged-in administrator. `php bones migrate:to-v3` lists the POST forms that do not print `csrfField()`. See [Migrating to v3](/docs/migrating-to-v3).
</Callout>

### Turning the check off

A page that receives a form posted from another site through the user's browser, a payment or sign-in provider returning to it for instance, cannot print the field. Turn the check off for that page only, with `'csrf' => false` in its `route`, in `config/menus.php` or `config/routes.php`:

```php copy {4}
  'route' => [
    'get'  => 'Dashboard\ConnectController@index',
    'post' => 'Dashboard\ConnectController@store',
    'csrf' => false,
  ],
```

A page in the `pages` folder turns it off with a public `csrf()` method, without arguments, that returns `false`: see [Pages Routing](pages-routing#forms). The page must then check the request itself, a signature for instance. A webhook, a call from another server, never reaches an admin page whatever this says: wp-admin asks for a logged-in browser first. Give it a [REST route](/docs/services-provider/rest-api).

## Form Method Spoofing

HTML forms do not support `PUT`, `PATCH` or `DELETE` actions. So, when defining `PUT`, `PATCH` or`DELETE` routes that are called from an HTML form, you will need to add a hidden `_method` field to the form. The value sent with the `_method` field will be used in the HTTP request:

```php copy
<form action="" method="POST">
    <?php echo $plugin->csrfField(); ?>
    <input type="hidden" name="_method" value="PUT">
</form>
```

## Resource

Alternatively, instead of specifying each single HTTP verb, you may use the `resource` key in order to call the default method in your view controller:

```php copy
...
  'route' => [ 'resource' => 'Dashboard\DashboardController' ],
...
```

Once you have assigned the view controller to a given route resource, you may use the standard methods instead.

```php copy
class DashboardResourceController extends Controller {
  
  // GET
  public function index() {
    //
  }
  
  // POST
  public function store() {
    //
  }
  
  // PUT AND PATCH
  public function update() {
    //
  }

  // DELETE
  public function destroy() {
    //
  }
}
```

You can use the `php bones` command to create a controller:

```sh copy
php bones make:controller MyController
```

Create the folder and namespace

```sh copy
php bones make:controller Billing/Market/MyController
```

## Redirect in load

When a submenu is clicked, your controller's methods are executed inside the admin view. This means that the HTTP headers are already sent. So, you can't execute any HTTP redirect but only a script - workaround - redirect. Anyway, WP Bones provides a redirect method that you may use. If the headers are already sent, a JavaScript script redirect will be done:

```php copy
// POST
public function store() {
  // your store command
  $this->redirect( 'some url' );
}
```

Also, WP Bones provides a special route called `load`. It is executed before the page is rendered:

```php copy
...
  'route' => [ 'load' => 'Dashboard\DashboardController@load' ],
...
```

<Callout>
You will need to use this method to add meta boxes.
</Callout>



```php copy
public function load()
{
    wp_enqueue_script( 'common' );
    wp_enqueue_script( 'wp-lists' );
    wp_enqueue_script( 'postbox' );
    
    // TODO: add your meta boxes
}
```

This route will be called on the `load-{hook}` action. Here you can use `wp_redirect()` or the WP Bones redirect method. Let's see an example:

```php copy
<form action="" method="post">
  <?php echo $plugin->csrfField(); ?>
  <input type="hidden" name="_redirect" value="http://undolog.com">
  <button class="button">POST with redirect</button>
</form>
```

In the `load` method of the controller:

```php copy
public function load()
{
  if( $this->request->get( '_redirect' ) ) {
    // the wp_redirect() will be done
    $this->redirect( $this->request->get( '_redirect' ) );
  }
}
```
