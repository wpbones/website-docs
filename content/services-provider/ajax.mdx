# Ajax

This document explains how to create and manage Ajax services in WP Bones. It covers three types of Ajax access: for logged-in users, not-logged-in users, and everyone. It provides steps to create an Ajax Service Provider using the `php bones make:ajax MyAjax` command and how to manually create one. The document also explains how to define actions for different user types and set capabilities and nonce keys for security: since `v3.0.0` an action for logged-in users always checks a nonce.

## Overview

In WordPress, you can have three different Ajax access:

-  Only for logged-in users
-  Only for not-logged-in users
-  For everyone

## Create an Ajax Service Provider

To create an Ajax Service Provider, you can use the following command:

```sh copy
php bones make:ajax MyAjax
```

By default, the new provider will be created in the `plugin/Ajax` directory. Of course, you may create your Service Provider manually and in any directory you prefer. You have to change the namespace accordingly.

```php filename="plugin/Ajax/MyAjax.php" copy
<?php
class MyAjax extends WordPressAjaxServiceProvider
{
  /**
   * List of the ajax actions executed by both logged and not logged users.
   * Here you will use a methods list.
   *
   * @var array
   */
  protected $trusted = ["trusted"];

  /**
   * List of the ajax actions executed only by logged-in users.
   * Here you will use a methods list.
   *
   * @var array
   */
  protected $logged = ["logged"];

  /**
   * List of the ajax actions executed only by the not logged-in user, usually from the frontend.
   * Here you will use a methods list.
   *
   * @var array
   */
  protected $notLogged = ["notLogged"];

  /**
   * You may also define the capability required to execute the action.
   */
  protected $capability = "manage_options";

  /**
   * The nonce key used to verify the request.
   *
   * @var string
   */
  protected $nonceKey = "nonce";

  /**
   * The nonce hash used to verify the request.
   *
   * @var string
   */
  protected $nonceHash = "wp_kirk_my_ajax";
}
```

<Callout type="warning">
Since `v3.0.0` the class `make:ajax` writes sets `$nonceHash` to its own name, and the requests to its `logged` actions send `wp_create_nonce()` of that name: without a `$nonceHash` they refuse every request. See [Nonce](#nonce).
</Callout>


## Edit the Ajax Service Provider

In the `\WPKirk\Ajax\MyAjax` class, you will list your methods/actions for logged-in, not logged-in, or trusted users:

The parent class `WordPressAjaxServiceProvider` will register on your behalf the WordPress actions that you need. So, let's have a look at a complete example:

```php copy
<?php
namespace WPKirk\Ajax;

use WPKirk\WPBones\Foundation\WordPressAjaxServiceProvider;

class MyAjax extends WordPressAjaxServiceProvider
{
  /**
   * List of the AJAX actions executed by both logged-in and not logged-in users.
   * Here you will use a methods list.
   *
   * @var array
   */
  protected $trusted = ["trusted"];

  /**
   * List of the AJAX actions executed only by logged-in users.
   * Here you will use a methods list.
   *
   * @var array
   */
  protected $logged = ["logged"];

  /**
   * List of the AJAX actions executed only by the not logged-in users, usually from the frontend.
   * Here you will use a methods list.
   *
   * @var array
   */
  protected $notLogged = ["notLogged"];

  /**
   * The capability required to execute the action.
   * Of course, this is only for logged-in users.
   *
   * @var string
   */
  protected $capability = "";

  /**
   * The nonce key used to verify the request.
   *
   * @var string
   */
  protected $nonceKey = "nonce";

  /**
   * The nonce hash used to verify the request.
   *
   * @var string
   */
  protected $nonceHash = "wp_kirk_my_ajax";

  public function trusted()
  {
    $response = "You have clicked Ajax Trusted";

    wp_send_json($response);
  }

  public function logged()
  {
    $response = "You have clicked Ajax Logged";

    wp_send_json($response);
  }

  public function notLogged()
  {
    $response = "You have clicked Ajax notLogged";

    wp_send_json($response);
  }
}
```

### Reading the request

`$this->useHTTPPost()` returns the POST values you name, in the same order, with `null` for a missing one:

```php copy
public function logged()
{
  [$name, $email] = $this->useHTTPPost('name', 'email');

  wp_send_json_success([
    'name' => sanitize_text_field($name ?? ''),
    'email' => sanitize_email($email ?? ''),
  ]);
}
```

Since `v3.0.0` the values come back without the slashes WordPress adds to every request value: `O'Brien` arrives as `O'Brien`. Up to 2.x `useHTTPPost()` returned the raw `$_POST` value, `O\'Brien`, and the code that called `wp_unslash()` on it can drop the call (a second `wp_unslash()` would strip a backslash the user typed).

You can also get the post variables by using `$this->request->get('post_name')`, which returns them as they are in `$_REQUEST`, with WordPress's slashes. WordPress provides several functions to return a JSON result. For example, you may use:

```php copy
wp_send_json_succcess();
```

or

```php copy
wp_send_json_success(["hello" => "world"]);
```

In JavaScript side, you'll find:

```javascript copy
$.post(ajaxurl, {}, function (response) {
  if (response.success) {
    // success property is set by WordPress wp_send_json_success
  } else {
    // also data property is set by WordPress wp_send_json_success
    // but it contains your custom array/object
    alert(response.data.hello);
  }
});
```

<Callout>
The `wp_send_json_error` function works in the same way.
</Callout>

## Security

The `logged` actions are protected by a nonce, which they always check since `v3.0.0`, and optionally by a capability. The `trusted` and `notLogged` actions check neither: anyone can call them, logged in or not, so keep them for what is public and check inside the method whatever needs checking.

### Capability

You can set the capability property in the class to protect the `logged` actions. For example, if you want to allow only the `manage_options` capability, you can set the `$capability` property to `manage_options`. A user without it gets a 403 JSON error.

### Nonce

Set the `$nonceHash` property, the action the nonce is created for, and send the nonce with every request in the field that `$nonceKey` names (`nonce` by default):

```php copy
/**
 * The nonce key used to verify the request.
 *
 * @var string
 */
protected $nonceKey = "nonce";

/**
 * The nonce hash used to verify the request.
 *
 * @var string
 */
protected $nonceHash = "wp_kirk_my_ajax";
```

<Callout type="info">
The `$nonceKey` property is the name of the post variable that will be sent to the server. The `$nonceHash` property is the string used to generate the nonce.
</Callout>

A request without the nonce, or with an invalid one, gets a 403 JSON error, and the action does not run. The nonce is read from the request, as `check_ajax_referer()` reads it: the form data (`application/x-www-form-urlencoded` or `multipart/form-data`), as the examples below send it, or the query string. A JSON body is not read: with one, put the nonce in the URL.

<Callout type="warning">
Since `v3.0.0` a provider with `logged` actions and an empty `$nonceHash` (or `$nonceKey`) refuses every request to them with a 403, and raises a `_doing_it_wrong()` notice that names the provider. Up to 2.x such a provider checked no nonce at all, so a page on another site could call its actions with the cookies of a logged-in user. `php bones migrate:to-v3` lists the providers that extend `WordPressAjaxServiceProvider` directly with `logged` actions and no `$nonceHash`; one that inherits it from a base class of your own is not listed. See [Migrating to v3](/docs/migrating-to-v3).
</Callout>

Next, you have to generate the nonce in your Controller and make it available to the JavaScript side. You can use the `withLocalizeScript` method to pass the nonce to the JavaScript side.

If you are using a ReactJS application, you may use something like this:

```php copy {7-8}
class DashboardController extends Controller
{
  public function index()
  {
    return WPKirk()
      ->view("dashboard.index")
      ->withLocalizeScript("app", "WPKirkNonce", [
        "nonce" => wp_create_nonce("wp_kirk_my_ajax"),
      ])
      ->withAdminAppsScript("app", true);
  }
}
```

The code above will create a global variable `WPKirkNonce` with the nonce value. You can use it in your ReactJS application like this:

```javascript copy
/**
 * Post data to the server.
 *
 * @param {string} action The action to be executed. Eg. "logged"
 * @returns {Promise<any>}
 */
const post = async action => {
  const res = await fetch(window.ajaxurl, {
    method: "POST",
    body: new URLSearchParams({
      action,
      nonce: WPKirkNonce.nonce,
    }),
    headers: {
      // form-data url encoded
      "Content-Type": "application/x-www-form-urlencoded",
    },
  });
  return res.json();
};
```

```javascript copy
post("logged").then(response => {
  console.log(response);
});
```

<Callout>
You may use the same also in Vanilla JavaScript or any other JavaScript framework. Most probably, in WordPress you are used to jQuery, so you can use the `$.post` method.

```javascript copy
$.post(
  ajaxurl,
  {
    action: "logged",
    nonce: WPKirkNonce.nonce,
  },
  function (data) {
    alert(data);
  }
);
```
</Callout>

## Load the Ajax Service Provider

To allow Ajax calls, you need to edit the `config/plugin.php` file. In the Ajax section, you can insert the list of your own Ajax classes, for example:

```php copy filename="config/plugin.php"
  /*
  |--------------------------------------------------------------------------
  | Ajax
  |--------------------------------------------------------------------------
  |
  | Here is where you can register your own Ajax actions.
  |
  */

  'ajax' => [ '\WPKirk\Ajax\MyAjax' ],
```
